# Security Policy

We take the security of this project seriously and appreciate responsible disclosure of any vulnerabilities.

## Reporting a Vulnerability

If you discover a security vulnerability, please report it using GitHub’s **Security Advisory feature**:

Go to the repository’s **Security** tab and click **“Report a vulnerability”**.

This ensures that the issue is handled privately and securely before any public disclosure.

Please avoid opening public issues for security vulnerabilities.

## Recommended Report Structure

When submitting a vulnerability report, please include as much detail as possible. We recommend using the following structure:

```
## Vulnerability Title
A short and descriptive title summarizing the issue.

### Summary
Short summary of the vulnerability.

### Details
Detailed description of the vulnerability, including relevant context and technical information.

### Impact
Description of the practical impact of the issue, including what an attacker could achieve.

### Environment
Specify the branch, tag, or commit hash used for testing.

### Steps to Reproduce
Explanation of how to reproduce the vulnerability, including proof-of-concept steps or code if available.

### Suggested Remediation
Optional suggestion for how to fix or mitigate the issue.
```

Thank you for helping keep this project secure.
